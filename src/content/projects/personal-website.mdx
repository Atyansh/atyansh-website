I'd put off building a real personal site since college. When I joined Anthropic I wanted to learn [Claude Code](https://claude.com/claude-code) properly, so I built this site with it. I haven't written any of its code by hand.

Besides the usual pages (work, papers, a blog, my [Project Euler solutions](/euler), a [PGP key](/pgp) and [my pets](/pets)), most of the site shows what I'm currently into: the games I'm playing, the music I listen to, the books, films, TV and anime I've finished, and my bouldering.

## Where the data comes from

The site is fully static. Everything is fetched at build time, and a build runs every night at 2 AM Pacific and on every push.

- **Games:** the Steam Web API; PlayStation Network's API, with a refresh token that rotates every build; Nintendo Switch play history scraped from Exophase in a headless browser; and IGDB for consistent box art across all three.
- **Music:** Spotify's API for top tracks, top artists, playlists and recent plays.
- **Movies:** my Letterboxd diary, ratings and posters, scraped.
- **TV:** a "watched" list and my ratings on TMDB.
- **Anime:** the MyAnimeList API.
- **Books:** Goodreads shelves, scraped with a signed-in session since Goodreads removed its RSS feeds in 2026.
- **Climbing:** Kaya's GraphQL API, for my grade pyramid, send history and send videos.

Most of these aren't stable APIs. Tokens expire on schedules from a day to a year, Letterboxd sits behind Cloudflare, and Goodreads and Trakt (which the TV page used to rely on) have both shut down the interfaces I started with. The interesting part of this project is keeping a page full of other people's data working every day without me looking at it.

## Keeping it running

- **Tokens refresh themselves.** Before each build a script tests the credentials that expire, renews them (MyAnimeList, PSN and IGDB tokens, plus a Goodreads re-sign-in when Amazon allows one) and writes any that changed back to Google Secret Manager in a single validated write. All credentials live in one JSON secret, and the last three versions are kept for rollback.
- **Bad data never replaces good data.** Each build starts from the previous build's cache. A source that fails, comes back empty, or returns less than half of what it had before keeps yesterday's data instead of blanking its page. Sources that can only be partly fetched, like Letterboxd past page 1 or Kaya's capped public queries, are merged onto the previous copy.
- **I hear about problems on Discord.** After every build a health check looks for a fresh cache file from each source and DMs me with what broke and how to fix it. Build or test failures DM me too, and a failed build never deploys. Where an expiry date is known in advance, as with the Goodreads login, the alert comes in the last 30 days rather than on the day.
- **The build has only the permissions it needs.** Cloud Build runs as a service account limited to deploying to Firebase, reading and updating its one secret, and its own storage bucket.

## The front end

Astro renders plain HTML, with React only where a page needs interactivity: the filterable media grids, the image viewer that grows out of a tile, and the music player. Songs play in place through a hidden Spotify embed that the page drives over `postMessage`, so the play buttons, progress ring and pop-up player are the site's own rather than Spotify's widget. Nothing on the media pages links away from the site.

There are five visual themes, from a clean default to a brutalist one and a dark terminal, switchable from the header. The site sends a strict Content Security Policy, and visits are counted with GoatCounter, which doesn't use cookies, rather than Google Analytics.

## Stack

- **Site:** Astro 7, React, Tailwind CSS 4, Framer Motion, TypeScript
- **Build:** Node.js 22, Vitest, Puppeteer for the scraped sources
- **Infrastructure:** Cloud Scheduler, Cloud Build (custom Docker image), Secret Manager, Firebase Hosting
- **Monitoring:** a Discord bot that DMs me

The whole thing is configurable for forks: identity, social links and each integration are switched on and off in one config file, and pages for disabled integrations aren't built.
